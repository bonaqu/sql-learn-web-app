# Course-health issue and duplicate register

## Duplicate search order

Before creating an issue, search open and closed GitHub issues by signal kind, lesson ID and task ID; search this register; then compare acceptance criteria. Update an existing issue when the same contract and root-cause hypothesis already exist.

## Priority policy

- P0: privacy leakage, data loss, false independent evidence, or blocking serious/critical accessibility defect.
- P1: reproducible learning-contract or navigation failure affecting multiple learners.
- P2: bounded content-quality hypothesis, clarity or non-blocking friction.

Synthetic scenario fixtures never create a real learner outcome issue by themselves. They may reveal a product-contract bug, but the issue must cite that exact reproducible contract rather than pretend the fixture is a participant.
