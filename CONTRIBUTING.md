# Разработка SQL Academy

## Основное правило

Изменения не вносятся напрямую в `bonaqu_projects`. Каждая самостоятельная работа выполняется в ветке и проходит через Pull Request.

## Пошаговый процесс

1. Создать ветку от актуальной `bonaqu_projects`:
   - `agent/<короткое-описание>` для работы AI-агента;
   - `feature/<короткое-описание>` для новой возможности;
   - `fix/<короткое-описание>` для исправления.
2. Внести один логически связанный набор изменений.
3. Проверить TypeScript, production build и Cloudflare dry run.
4. Открыть Pull Request в `bonaqu_projects`.
5. Дождаться зелёного workflow `Pull Request Quality`.
6. Просмотреть diff, риски, мобильную версию и конфиденциальность.
7. Выполнить squash merge.
8. GitHub Pages и Cloudflare разворачиваются только после merge.

## Обязательные требования

- Не добавлять персональные данные владельца проекта.
- Не хранить токены, API-ключи и идентификаторы доступа в репозитории.
- Не использовать платные Cloudflare-возможности без явного решения владельца.
- Для интерфейсных изменений проверять desktop и mobile.
- Для учебных задач проверять эталонный результат, а не текст SQL.
- Для D1 использовать миграции; существующие данные нельзя ломать без стратегии обновления.

## Коммиты и Pull Requests

Коммит должен описывать одно изменение. Pull Request должен объяснять пользовательский эффект, проверки, риски и откат.
